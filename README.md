# Stomper Hyperion 5.0 — web port

[![Netlify Status](https://api.netlify.com/api/v1/badges/1ed121d0-6a56-43cd-ab84-2c40070224a9/deploy-status)](https://app.netlify.com/projects/fastidious-cobbler-4c6f7e/deploys)

A browser port of the 1999/2000 software synthesizer **STOMPER32.EXE**. The sound
engine, the 64-slot oscillator model, the `.STU`/`.STP` file format and the
envelope/FM/AM/filter behaviour were recovered statically from the original
binary; the UI was rebuilt with modern web technologies.

The app is a zero-runtime-dependency Vite + TypeScript project. All DSP runs in
an `AudioWorkletProcessor` (with a main-thread fallback when `AudioWorklet` is
unavailable). Live playback uses the device sample rate; offline export uses the
song's selected rate, with the same mixer code, so exports are sample-identical
to an offline render of the song.

## Quick start

Requires Node.js 22 or newer.

```bash
npm install
npm run dev          # http://127.0.0.1:5173
```

Production build and local preview:

```bash
npm run build
npm run preview      # http://127.0.0.1:4173
```

Other scripts:

```bash
npm test             # Node's built-in test runner (36 tests)
npm run typecheck    # tsc --noEmit
```

## Features

- 64 oscillator slots, each with enable state Off / On / Inaudible, role
  Oscillator / Filter, waveform Sine / Saw / Square / Triangle / WAV file.
- Time and amplitude envelopes with independent `CurveShape0` / `CurveShape1`
  exponents and a waveform-shaping exponent `CurveShape2`.
- Frequency and amplitude glide, noise (including the original MSVC `_rand()`
  sequence), FM and AM routing between slots.
- Sequential, order-dependent mixing: a filter processes everything mixed
  before it, exactly like `FUN_004083B0`.
- Envelope editor with absolute or snapped dragging, display modes Hz/Note and
  ms/beat:fraction, and snapping to notes or beat fractions.
- Multi-level undo, cut/copy/paste, insert/delete oscillator, context menu.
- Open and save `.STU`/`.STP` INI files; loading a file adopts its sample rate.
- WAV sample loading for waveForm 4.
- Play/Stop is a single transport toggle. It flips back to Play when the song
  ends naturally.
- Sample rates 22050, 44100 and 48000 Hz (48000 is the default).
- Normalize and 16-bit mono WAV export using the original's 32760.0 scale and
  truncating conversion.
- Built-in demo song (`Special → Demo Song`).

## File format

`.STU` and `.STP` are INI files with a `[Common]` section (`SampleFrequency`,
`Oscillators`) and one `[Oscillator N]` section per slot. The port reads and
writes the same key set as the original, including `FMModBy`/`AMModBy`,
`StartT`/`EndT` in milliseconds, and `Enabled=-1` (treated as On). Unknown keys
are ignored, and missing keys fall back to the original defaults.

## Verification

The [`tests/examples/`](tests/examples/) directory contains 47 `.STU`/`.STP`
songs and WAV renders made by the original binary. The port is checked against
them as follows:

- The reference WAVs that contain no noise reproduce to **at most 1 LSB** of
  difference (`Example1`–`Example5` are covered by `tests/render.test.ts`).
- The original writes samples by clamping to `[-1, 1]`, multiplying by
  **32760.0** (not 32767.0) and truncating toward zero. The web writer does the
  same.
- Sine oscillators use the binary's **truncated 2π constant** `6.2831852` from
  `0x00437788`, not the correctly rounded `Math.PI * 2`; the tiny relative
  difference accumulates over long renders.
- Filters normalise with the original's integer division:
  `norm = trunc(rate / 10000) * rate`.

### Noise and the reference renders

Noise is generated by MSVC's unseeded LCG (`holdrand = 1`, no `_srand`). The
reference WAVs were rendered over several original sessions, so their noise
depends on the accumulated `_rand()` history of those sessions. A fresh web
render therefore cannot reproduce those files bit-for-bit unless it starts at
the same RNG offset. `src/dsp/noise.ts` implements the exact LCG, and the
engine resets to seed 1 for every render, which is the deterministic
fresh-process behaviour.

Where a reference file's RNG offset has been recovered, the port matches it to
**≤ 1 LSB** (for example `Hat1.stp`, `Bad-clap.stp`, `Simmons.stp` and
`Fx-kafop.stp`). The remaining residuals in `K909-1/2`, `Kdance`, `Kjungle` and
`Kdist` are x87-vs-JavaScript floating-point precision in fractional powers and
long filter feedback, not logic differences.

## Browser notes

- `AudioWorklet` is only exposed in secure contexts (`https:` or
  `http://localhost`). On plain HTTP origins the app automatically falls back
  to a main-thread renderer that feeds an `AudioBufferSourceNode`.
- The worklet keeps its own frame counter; it does not rely on the
  non-standard `sampleIndex` global.
- `window.stomper` is exposed for debugging and for the browser smoke test.

  model/     types, INI reader/writer, store/undo, built-in songs
  dsp/       engine init, mixer, waveform generator, MSVC noise LCG
  audio/     worklet, playback session, offline render, WAV writer, decoding

## Scope

TUAREG integration, the ZapNews feed and the original trial/expiry check are
intentionally not ported. The "demo song" menu entry no longer opens the
defunct web page; it loads a self-contained song built from the oscillator
model.

## Smoke test

With Chrome installed:

```bash
npm run build
npx vite preview --port 4173 &
node tools/smoke.mjs
```

The script drives the built app through the DevTools protocol and checks the
UI, oscillator insertion, context menu, undo, demo loading, playback, export,
display modes, save and `.STU` round-trip, plus console health.
